## Context

During routine host audits on multi-user Linux systems, overly broad file permissions (`777` or `666`) on scripts or configuration files remain one of the most common misconfigurations.

## Detection Commands

To inspect world-writable files safely inside a specific test directory without scanning restricted paths:

```bash
find ./workspace -type f -perm -0002 -ls
```

## Remediation

Apply the principle of least privilege using explicit owner and group permissions:

```bash
chmod 640 ./workspace/app.conf
chmod 750 ./workspace/run-backup.sh
```

## Key Takeaway

Never use `chmod 777` as a shortcut to fix permission errors. Identify which user or service group genuinely requires access and grant only the minimum required mode bits.
