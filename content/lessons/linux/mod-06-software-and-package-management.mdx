# **Module 06 — Software and Package Management**



## **A. Welcome to Software and Package Management**

Linux applications are commonly distributed as **software packages**. Instead of manually downloading and installing every application, Linux provides tools that manage software installation, updates, and removal.

A **package manager** works like a trusted software store. It helps you find applications, install them, check for updates, and remove software you no longer need.

Package management is important because Linux users and cybersecurity practitioners regularly need to install tools, apply security updates, and inspect the software available on a system.

In this module, you will learn how to manage software using APT on Debian- and Ubuntu-based Linux distributions.

## **B. Understanding Packages and APT**

### **What is a software package?**

A **software package** is a collection of files and information prepared for installation on a Linux system.

A package may contain:

- Application files.
- Configuration files or templates.
- Information about the package.
- Instructions used during installation and removal.

A package and an application are related, but they are not exactly the same thing. An application is the software you use; a package is the organized unit used to distribute and install that software.

### **What is a package manager?**

A package manager is a tool that manages software on your system.

It helps you:

- Search for available software.
- Install applications.
- Update installed software.
- Remove unwanted packages.
- Inspect package information.

### **What is a software repository?**

A **software repository** is a server or collection of servers that provides software packages and package information.

Your Linux system uses configured repositories to find available packages.

For example, Ubuntu provides official repositories containing many commonly used applications and utilities.

### **What is APT?**

APT stands for **Advanced Package Tool**.

It is the package-management tool commonly used on Debian and Ubuntu-based distributions.

You will use APT for most of the practical tasks in this module.

**Basic APT workflow**

1. **Refresh package information**

   `sudo apt update`
2. **Search for software**

   `apt search package-name`
3. **Inspect package details**

   `apt show package-name`
4. **Install software**

   `sudo apt install package-name`
5. **Verify the installation**

   `dpkg -l package-name`

## **C. Refreshing Package Information**

Before installing or upgrading software, it is good practice to refresh your package information.

Use:

```
sudo apt update
```

This command contacts your configured repositories and retrieves the latest available package information.

### **What is package information?**

Package information includes details such as:

- Available package names.
- Available package versions.
- Package descriptions.
- Information about software available from configured repositories.

APT uses this information to determine which packages are available for installation and whether newer versions exist.

### **Example output**

```
Hit:1 http://archive.ubuntu.com/ubuntu noble InRelease
Get:2 http://archive.ubuntu.com/ubuntu noble-updates InRelease
Get:3 http://security.ubuntu.com/ubuntu noble-security InRelease
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
```

Your output may look different depending on your distribution, configured repositories, and network connection.

Important things to notice:

- `Hit`: Existing repository information was already current.
- `Get`: APT retrieved information from a repository.
- `Reading package lists... Done`: APT finished processing the package information.

**Important distinction**

`sudo apt update` refreshes package information. It does not install available updates or upgrade your applications.

The command uses `sudo` because updating the system's package information requires administrative privileges.

## **D. Upgrading Installed Software**

After refreshing package information, you can upgrade installed software.

Use:

```
sudo apt upgrade
```

This command upgrades installed packages when newer versions are available and can be installed through the normal upgrade process.

Software updates may contain:

- Security fixes.
- Bug fixes.
- Performance improvements.
- New features.

### **Example output**

```
Reading package lists... Done
Building dependency tree... Done
Reading state information... Done
The following packages will be upgraded:
  curl openssl
2 upgraded, 0 newly installed, 0 to remove.
Need to get 1,250 kB of archives.
After this operation, 120 kB of additional disk space will be used.
Do you want to continue? [Y/n]
```

This is an illustrative example. The actual packages and numbers will vary.

APT may ask for confirmation before continuing.

Read the information carefully before entering `Y`.

If you do not want to proceed, enter `n`.

### **Understanding update vs upgrade**

These two commands perform different jobs:

| Command            | What it does                                     |
| ------------------ | ------------------------------------------------ |
| `sudo apt update`  | Refreshes package information from repositories. |
| `sudo apt upgrade` | Upgrades installed packages when possible.       |

A simple way to remember:

- `update` checks what software information is available.
- `upgrade` applies available upgrades to installed packages.

**Safety tip:** Do not casually interrupt an upgrade while packages are being installed or configured. Let it finish unless there is a genuine problem.

## **E. Searching for Software**

Before installing an application, you should find out whether it is available in your configured repositories.

APT provides the `search` command.

### **Search for a package**

For example, search for `tree`:

```
apt search tree
```

APT displays packages whose names or descriptions match your search.

Example output:

```
Sorting... Done
Full Text Search... Done
tree/noble 2.1.1-2ubuntu3 amd64
  displays an indented directory tree, in color
```

The exact version and output may differ.

You can use search results to identify a suitable package.

### **Inspect package information**

After finding a package, use `apt show` to inspect it.

```
apt show tree
```

Example output:

```
Package: tree
Version: 2.1.1-2ubuntu3
Priority: optional
Section: utils
Installed-Size: 116 kB
Description: displays an indented directory tree
```

This output is illustrative.

Pay attention to:

- `Package`: The package name.
- `Version`: The package version.
- `Installed-Size`: Approximate installed size.
- `Description`: What the software does.

Searching and inspecting software before installation helps you make a more informed decision.

## **F. Installing Software**

Once you have identified the package you want, you can install it using:

```
sudo apt install package-name
```

Replace `package-name` with the name of the package you want to install.

### **Example: Install tree**

The `tree` utility displays files and directories in a tree-like structure.

Install it using:

```
sudo apt install tree
```

APT checks the package information and prepares the installation.

Example output:

```
The following NEW packages will be installed:
  tree
0 upgraded, 1 newly installed, 0 to remove.
Need to get 52.0 kB of archives.
Do you want to continue? [Y/n]
```

This is illustrative output; actual details depend on your system.

When APT asks for confirmation:

- Enter `Y` to continue.
- Enter `n` to cancel.

APT may also install additional packages called **dependencies**. These are other software components required by the package you are installing.

You do not normally need to install these dependencies manually.

### **Verify that the program works**

After installation, run:

```
tree --version
```

Example output:

```
tree v2.1.1
```

You can also run:

```
tree
```

This displays the directory structure of your current location.

Example output:

```
.
├── Documents
├── Downloads
├── Music
└── Pictures
```

Your directory structure will probably be different.

**Remember:** Package names and availability can vary between distributions and enabled repositories.

## **G. Removing Software**

Sometimes you may want to remove an application that you no longer need.

APT provides two common commands:

- `apt remove`
- `apt purge`

### **1. Remove a package**

Basic syntax:

```
sudo apt remove package-name
```

For example:

```
sudo apt remove tree
```

This uninstalls the `tree` package but generally leaves its system-wide package-managed configuration files.

APT may ask for confirmation before removing the package.

### **2. Purge a package**

Basic syntax:

```
sudo apt purge package-name
```

For example:

```
sudo apt purge tree
```

This removes the package and its package-managed system-wide configuration files.

It does not necessarily remove every file associated with the application. For example, user-created files and configuration stored in your home directory may remain.

### **Remove vs purge**

| Command                | Result                                                                            |
| ---------------------- | --------------------------------------------------------------------------------- |
| `sudo apt remove tree` | Uninstalls the package but generally retains system-wide package configuration.   |
| `sudo apt purge tree`  | Uninstalls the package and removes its package-managed system-wide configuration. |

### **3. Remove unused dependencies**

APT may install additional packages as dependencies.

When those packages are no longer needed by installed software, APT may identify them as removable.

Use:

```
sudo apt autoremove
```

APT displays the packages it proposes to remove.

**Important:** Always review the removal list before confirming. Do not approve the operation if you do not understand why an important package is listed.

You do not need to run `remove`, `purge`, or `autoremove` just to complete the main practice exercise.

## **H. Listing Installed Packages**

Linux provides the `dpkg` package-management utility, which can display information about packages installed on Debian-based systems.

To list package information, run:

```
dpkg -l
```

This displays a list of packages and their installation status.

Example output:

```
Desired=Unknown/Install/Remove/Purge/Hold
| Status=Not/Inst/Conf-files/Unpacked/...
||/ Name       Version       Architecture Description
+++-==========-=============-============-========================
ii  curl       8.5.0-2ubuntu10 amd64       command line tool for...
ii  tree       2.1.1-2ubuntu3 amd64       displays directory trees
```

The output is abbreviated and illustrative.

The `ii` status at the beginning of a row indicates that the package is desired for installation and is currently installed.

### **Inspect a particular package**

Instead of displaying every package, you can inspect one package:

```
dpkg -l tree
```

If `tree` is installed, you should see its package entry.

If it is not installed, the output will indicate that no matching installed package was found.

This is a useful way to verify whether a package is installed.

## **I. Trusted Repositories and Basic Safety**

Installing software is a normal part of Linux administration, but you should always consider where the software comes from.

### **Use trusted repositories**

Prefer official repositories provided by your Linux distribution.

They provide a more reliable way to obtain software than downloading unknown installation files from random websites.

### **Be careful with installation scripts**

You may encounter commands online that download and immediately execute a script.

For example, a command that downloads a script and pipes it directly into a shell can run code before you have inspected what it does.

Avoid running unfamiliar installation commands without understanding them.

### **Check package names**

Similar package names can refer to different applications.

Before installing something:

1. Search for the package.
2. Inspect its description.
3. Check that the package name is correct.
4. Confirm that the source is trusted.

### **Be careful with sudo**

Running an unknown command with `sudo` can allow it to modify protected system files or change important system settings.

Never use elevated privileges simply because a website or tutorial tells you to.

**Basic software safety checklist**

- Use trusted software repositories.
- Check package names before installing.
- Read APT confirmation prompts.
- Avoid unknown installation scripts.
- Understand commands before running them with `sudo`.

## **J. Hands-on Practice — Install and Inspect a Linux Utility**

In this exercise, you will install and test `tree`.

The exercise uses one small utility and does not require advanced system configuration.

### **Step 1: Refresh package information**

Run:

```
sudo apt update
```

**What it does:** Retrieves the latest package information from configured repositories.

**Expected result:** APT finishes reading the package lists without a fatal error.

**Privileges:** Requires administrative privileges.

### **Step 2: Search for tree**

Run:

```
apt search tree
```

**What it does:** Searches available package information for packages matching `tree`.

**Expected result:** You should find a package named `tree` if it is available in your configured repositories.

**Privileges:** Does not normally require `sudo`.

### **Step 3: Inspect package information**

Run:

```
apt show tree
```

**What it does:** Displays details about the `tree` package.

Look for:

- Package name.
- Version.
- Installed size.
- Description.

**Expected result:** APT displays information about the package if it is available.

**Privileges:** Does not normally require `sudo`.

### **Step 4: Install tree**

Run:

```
sudo apt install tree
```

**What it does:** Installs the `tree` utility.

APT may display additional dependencies and ask for confirmation.

Enter:

```
Y
```

**Expected result:** APT downloads and installs the package.

**Privileges:** Requires administrative privileges.

### **Step 5: Verify the installation**

Run:

```
tree --version
```

**What it does:** Displays the installed program's version.

Example output:

```
tree v2.1.1
```

**Expected result:** A version number appears, confirming that the command can run.

**Privileges:** Does not require `sudo`.

### **Step 6: Run the utility**

First, create a small practice directory:

```
mkdir -p ~/module06-practice/Documents
mkdir -p ~/module06-practice/Downloads
touch ~/module06-practice/Documents/notes.txt
touch ~/module06-practice/Downloads/sample.txt
```

These commands create a directory structure and two empty files inside your home directory.

Now move into the practice directory:

```
cd ~/module06-practice
```

Run:

```
tree
```

Example output:

```
.
├── Documents
│   └── notes.txt
└── Downloads
    └── sample.txt

3 directories, 2 files
```

**What it does:** Displays the directory structure in a tree format.

**Expected result:** You should see the two directories and their files.

**Privileges:** Does not require `sudo`.

### **Step 7: Inspect the installed package**

Run:

```
dpkg -l tree
```

Example output:

```
ii  tree  2.1.1-2ubuntu3  amd64  displays an indented directory tree
```

**What it does:** Displays the installation status and details of the `tree` package.

**Expected result:** The package appears with the `ii` status, indicating that it is installed.

**Privileges:** Does not require `sudo`.

### **Optional Step 8: Remove tree**

Only perform this step if you no longer want to keep the utility.

Run:

```
sudo apt remove tree
```

APT will display the packages it intends to remove and ask for confirmation.

Review the list before proceeding.

**What it does:** Uninstalls `tree` while generally retaining its system-wide package-managed configuration files.

**Privileges:** Requires administrative privileges.

You can verify its removal using:

```
dpkg -l tree
```

If you want to keep `tree` installed, skip this optional step.
