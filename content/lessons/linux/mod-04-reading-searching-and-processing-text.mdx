## **A. Welcome to Reading and Processing Text**

Linux systems generate and store a lot of information in text files.

These files may contain application activity, login attempts, system events, configuration settings, and other useful information.

In cybersecurity, examining this information is an important everyday activity.

For example, imagine you are investigating a suspicious login attempt. You might need to:

- Read an application log.
- Find failed login attempts.
- Identify timestamps and IP addresses.
- Count how many times an event occurred.
- Extract useful information into another file.

Reading every line manually would take too much time.

Think of a large notebook containing thousands of entries. Instead of reading every page, you want to search for a particular word, count matching entries, and organize the results.

Linux provides commands that make this possible.

In this module, you will learn how to read, search, count, sort, and extract information from text files.

Let's start practicing.

## **B. Reading Text Files**

Linux provides several commands for displaying text file contents.

You already learned `cat` in Module 03. Now let's explore some additional commands that make reading files easier.

### **1.&#x20;**`cat`**&#x20;— Display File Contents**

The `cat` command displays the contents of a text file directly in the terminal.

**Syntax:**

```
cat filename
```

**Example:**

```
cat notes.txt
```

**Possible output:**

```
Linux Fundamentals
Learning Linux commands
Practicing cybersecurity
```

**When should you use it?**

Use `cat` when you want to display a short file quickly.

However, displaying a very large file using `cat` may fill your terminal with too much information.

For large files, other commands are more convenient.

### **2.&#x20;**`less`**&#x20;— Read Files Page by Page**

The `less` command allows you to read a file one screen at a time.

**Syntax:**

```
less filename
```

**Example:**

```
less application.log
```

Instead of printing the entire file, `less` opens an interactive viewer.

**Useful keyboard shortcuts:**

| Key          | Action                      |
| ------------ | --------------------------- |
| `Space`      | Move forward one screen.    |
| `b`          | Move backward one screen.   |
| `Arrow Down` | Move down one line.         |
| `Arrow Up`   | Move up one line.           |
| `/word`      | Search forward for a word.  |
| `n`          | Find the next search match. |
| `q`          | Exit `less`.                |

**When should you use it?**

Use `less` when working with large logs, reports, or configuration files that you don't want to print entirely.

### **3.&#x20;**`head`**&#x20;— Display the Beginning of a File**

The `head` command displays the first lines of a file.

**Syntax:**

```
head filename
```

By default, it displays the first 10 lines.

**Example:**

```
head application.log
```

To display a specific number of lines, use `-n`.

```
head -n 5 application.log
```

This displays only the first five lines.

**Possible output:**

```
2026-11-16 08:00:01 INFO Application started
2026-11-16 08:01:10 INFO User student logged in
2026-11-16 08:02:15 INFO Dashboard accessed
2026-11-16 08:03:20 INFO Configuration loaded
2026-11-16 08:04:30 INFO Database connection established
```

**When should you use it?**

Use `head` when you want to quickly inspect the beginning of a file.

### **4.&#x20;**`tail`**&#x20;— Display the End of a File**

The `tail` command displays the last lines of a file.

**Syntax:**

```
tail filename
```

By default, it displays the last 10 lines.

To display only the last five lines:

```
tail -n 5 application.log
```

**When should you use it?**

Use `tail` when you want to inspect the most recent entries in a log file.

### **5.&#x20;**`tail -f`**&#x20;— Watch New Log Entries**

The `tail -f` command allows you to watch a file as new lines are added.

**Example:**

```
tail -f application.log
```

When another process writes new lines to the file, they appear in your terminal.

This is useful when observing application logs during testing.

To stop watching the file, press:

```
Ctrl + C
```

**Remember:** `tail -f` is useful for observing ongoing activity, but it does not independently analyze or interpret the events.

### **Quick Comparison**

| Command   | Purpose                          |
| --------- | -------------------------------- |
| `cat`     | Display the complete file.       |
| `less`    | Read a file page by page.        |
| `head`    | Display the beginning of a file. |
| `tail`    | Display the end of a file.       |
| `tail -f` | Watch new lines as they appear.  |

## **C. Searching Text with grep**

One of the most useful Linux commands for cybersecurity beginners is `grep`.

The `grep` command searches for specific text patterns inside files.

Imagine an application log containing thousands of lines. You only want to find entries containing the word `FAILED`.

Instead of reading the entire file, you can use `grep`.

### **1. Basic grep Command**

**Syntax:**

```
grep "pattern" filename
```

**Example:**

```
grep "FAILED" application.log
```

This searches for lines containing `FAILED`.

**Possible output:**

```
2026-11-16 08:15:22 AUTH FAILED user=admin ip=192.0.2.15
2026-11-16 08:18:40 AUTH FAILED user=student ip=198.51.100.20
```

The command displays only the matching lines.

### **2. Case-Insensitive Search Using&#x20;**`-i`

By default, `grep` distinguishes between uppercase and lowercase letters.

For example, these are different:

```
FAILED
failed
Failed
```

To search without considering letter case, use `-i`.

**Example:**

```
grep -i "failed" application.log
```

This can match `FAILED`, `failed`, and `Failed`.

### **3. Display Line Numbers Using&#x20;**`-n`

Sometimes you want to know where a matching entry appears inside a file.

Use the `-n` option.

**Example:**

```
grep -n "FAILED" application.log
```

**Possible output:**

```
6:2026-11-16 08:15:22 AUTH FAILED user=admin ip=192.0.2.15
9:2026-11-16 08:18:40 AUTH FAILED user=student ip=198.51.100.20
```

The numbers at the beginning indicate the matching line numbers.

### **4. Search Recursively Using&#x20;**`-r`

You can search through files inside a directory and its subdirectories using `-r`.

**Syntax:**

```
grep -r "pattern" directory/
```

**Example:**

```
grep -r "ERROR" logs/
```

This searches files inside `logs/` and its subdirectories for the word `ERROR`.

### **5. Count Matching Lines Using&#x20;**`-c`

If you only want to know how many lines contain a particular pattern, use `-c`.

**Example:**

```
grep -c "FAILED" application.log
```

**Possible output:**

```
2
```

This means two lines contain the matching text.

It counts matching lines, not necessarily the total number of occurrences of the word.

### **Quick Comparison**

| Command                      | Purpose                          |
| ---------------------------- | -------------------------------- |
| `grep "FAILED" file`         | Search for matching text.        |
| `grep -i "failed" file`      | Search without case sensitivity. |
| `grep -n "FAILED" file`      | Display matching line numbers.   |
| `grep -r "ERROR" directory/` | Search recursively.              |
| `grep -c "FAILED" file`      | Count matching lines.            |

**Cybersecurity tip**

Finding a matching line does not automatically mean an attack occurred.

For example, a failed login may result from a user entering the wrong password.

Always examine the surrounding information and context before drawing conclusions.

## **D. Counting Text with wc**

The `wc` command helps you count information inside text files.

It can count:

- Lines.
- Words.
- Bytes.

### **1.&#x20;**`wc`**&#x20;— Count Lines, Words and Bytes**

**Syntax:**

```
wc filename
```

**Example:**

```
wc application.log
```

**Possible output:**

```
12  96  1050 application.log
```

The output represents:

| Value  | Meaning          |
| ------ | ---------------- |
| `12`   | Number of lines. |
| `96`   | Number of words. |
| `1050` | Number of bytes. |

The exact values depend on the file contents.

### **2. Count Lines Using&#x20;**`-l`

To count only the lines:

```
wc -l application.log
```

**Possible output:**

```
12 application.log
```

### **3. Count Words Using&#x20;**`-w`

To count the words:

```
wc -w application.log
```

**Possible output:**

```
96 application.log
```

### **4. Count Bytes Using&#x20;**`-c`

To count the bytes:

```
wc -c application.log
```

**Possible output:**

```
1050 application.log
```

**When should you use&#x20;**`wc`**?**

You might use it to determine how many entries a log contains, how many lines a search returned, or how large a text file is.

**Remember:** `wc -c` counts bytes, not necessarily human-readable characters. For ordinary ASCII text, the counts are generally the same.

## **E. Sorting Text with sort**

The `sort` command arranges lines of text into a particular order.

This is useful when you want to organize usernames, IP addresses, or other text-based information.

### **1.&#x20;**`sort`**&#x20;— Sort Alphabetically**

Suppose you have a file named `users.txt` containing:

```
charlie
alice
bob
david
```

Execute:

```
sort users.txt
```

**Output:**

```
alice
bob
charlie
david
```

The command sorts the lines alphabetically.

### **2.&#x20;**`sort -n`**&#x20;— Sort Numerically**

The `-n` option sorts numbers based on their numerical values rather than their alphabetical order.

Suppose `numbers.txt` contains:

```
100
20
5
40
```

Execute:

```
sort -n numbers.txt
```

**Output:**

```
5
20
40
100
```

### **3.&#x20;**`sort -r`**&#x20;— Reverse Sorting**

The `-r` option reverses the sorting order.

**Example:**

```
sort -r users.txt
```

**Output:**

```
david
charlie
bob
alice
```

You can also combine options:

```
sort -nr numbers.txt
```

This sorts numbers numerically in reverse order.

**What should you remember?**

| Command             | Purpose                            |
| ------------------- | ---------------------------------- |
| `sort file.txt`     | Sort alphabetically.               |
| `sort -n file.txt`  | Sort numerically.                  |
| `sort -r file.txt`  | Reverse sorting.                   |
| `sort -nr file.txt` | Sort numerically in reverse order. |

## **F. Extracting Fields with cut**

Sometimes you don't need an entire line of information.

You only want a particular part of it.

The `cut` command helps extract selected sections or fields from each line of a text file.

This is particularly useful when working with structured text.

### **1. Understanding Fields**

Imagine you have a file named `users.csv` containing:

```
alice,admin,active
bob,student,inactive
charlie,student,active
```

Each line contains three fields separated by commas.

The fields represent:

1. Username.
2. Role.
3. Account status.

You may only want to extract the usernames.

### **2. Using&#x20;**`cut -d`**&#x20;and&#x20;**`cut -f`

The `-d` option specifies the delimiter, meaning the character separating the fields.

The `-f` option selects which field to display.

**Basic syntax:**

```
cut -d "delimiter" -f field_number filename
```

**Example: Extract Usernames**

```
cut -d "," -f 1 users.csv
```

**Output:**

```
alice
bob
charlie
```

The command uses the comma as a separator and displays the first field.

### **3. Extract Another Field**

To extract the second field:

```
cut -d "," -f 2 users.csv
```

**Output:**

```
admin
student
student
```

To extract the third field:

```
cut -d "," -f 3 users.csv
```

**Output:**

```
active
inactive
active
```

### **4. Using a Different Delimiter**

You can also work with colon-separated text.

For example, consider:

```
alice:admin:active
bob:student:inactive
```

To extract the usernames:

```
cut -d ":" -f 1 users.txt
```

**Output:**

```
alice
bob
```

**When should you use&#x20;**`cut`**?**

Use it when you want to extract specific fields from consistently structured text files.

It is useful for working with simple CSV files, colon-separated records, and other structured text.

## **G. Input, Output and Pipes**

Linux commands can receive information, display results, and pass information to other commands.

Understanding these basic concepts will help you work more efficiently in the terminal.

Let's introduce three important terms.

### **1. Standard Input, Output and Error**

Linux commonly uses three standard data streams.

| Stream                     | Description                           |
| -------------------------- | ------------------------------------- |
| Standard Input (`stdin`)   | Information a command receives.       |
| Standard Output (`stdout`) | Normal output produced by a command.  |
| Standard Error (`stderr`)  | Error messages produced by a command. |

For example, when you execute:

```
ls
```

The filenames are normally displayed through standard output.

If you execute a command that references a nonexistent file, an error message is normally displayed through standard error.

You don't need to manage these streams manually yet. Just understand their basic purpose.

### **2. Output Redirection Using&#x20;**`>`

The `>` symbol redirects command output into a file.

**Example:**

```
ls > files.txt
```

This saves the output of `ls` into a file named `files.txt`.

Instead of displaying the directory listing in your terminal, Linux writes it into the file.

You can inspect the result:

```
cat files.txt
```

**Important:** If `files.txt` already exists, `>` replaces its existing contents.

### **3. Append Output Using&#x20;**`>>`

The `>>` symbol also redirects output, but it adds the new information to the end of an existing file.

**Example:**

```
echo "Linux practice completed" >> notes.txt
```

This adds the text to the end of `notes.txt`.

It does not replace the existing contents.

To inspect the file:

```
cat notes.txt
```

### **Difference Between&#x20;**`>`**&#x20;and&#x20;**`>>`

**Using&#x20;**`>`**&#x20;— Replace existing contents**

```
echo "First entry" > log.txt
```

If log.txt already contains information, that content is replaced.

**Using&#x20;**`>>`**&#x20;— Append new contents**

```
echo "Second entry" >> log.txt
```

The new text is added after the existing content.

### **4. Pipes Using&#x20;**`|`

A pipe allows you to connect two commands.

It takes the standard output of the first command and passes it as standard input to the second command.

**Example:**

```
ls | wc -l
```

Let's understand what happens:

1. `ls` lists the files and directories.
2. `|` passes that output to the next command.
3. `wc -l` counts the lines it receives.

**Possible output:**

```
8
```

This tells you that the listing produced eight lines.

### **5. Search Command Output Using a Pipe**

You can also combine commands to find useful information.

**Example:**

```
cat application.log | grep "FAILED"
```

This displays lines containing `FAILED` from the output of `cat`.

A simpler and more direct approach for this particular task is:

```
grep "FAILED" application.log
```

Both demonstrate how commands can be connected, but the second avoids an unnecessary extra command.

**Remember:**

- `>` replaces existing file contents.
- `>>` appends to existing file contents.
- `|` passes one command's standard output to another command's standard input.
